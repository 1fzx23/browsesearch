真正从浏览器里联网搜索

browsesearch 不是调某个搜索 API，而是直接驱动一个真实的 Chromium 无头浏览器去打开搜索引擎、等 JS 把结果渲染出来，再读取 DOM。没有 API key，不被轻易反爬挡掉。

命令行用法

// CLI

安装

pip install "browsesearch[browser]" 装真实浏览器模式（会顺带下载 Chromium）；只想用 HTTP 回退就 pip install browsesearch。

搜索

python browsesearch.py "关键词" 默认 DuckDuckGo + 真实浏览器。换引擎：-e bing / -e google。

格式化输出

-f json 拿结构化结果（含 rank / score），-f md 拿 Markdown，方便接进脚本或笔记。

相关度排序与 Top

默认按匹配度降序排列，每条带 score。用 --top 3 只取最匹配的前 3 条；--sort engine 可恢复搜索引擎原始顺序。默认一次抓满 30 条（跨页去重）。

打开结果

加 --open 用系统默认浏览器直接打开第一条结果；--no-headless 让浏览器以窗口形式出现。

启动 AI 调用接口

--serve --port 8731 起一个零依赖本地 HTTP API，让 AI / 脚本直接调 /search 读 JSON（见下方「AI 调用」）。

相关度排序 · 找最匹配的那条

// relevance
🎯

自动打分

对每条结果的标题与摘要，按查询词命中情况算一个 score：整句命中标题 +5、单词命中标题 +2、命中摘要 +0.5、覆盖率再加权。

📊

降序排列

返回结果默认按 score 从高到低，第一条就是最匹配；JSON 里会带 rank 与 score，一眼看出谁最相关。

🔝

Top N

只要最相关的几条？--top 5 直接返回按相关度排好的前 5 条，省去自己再筛。

📚

至少 30 条

默认一次抓满 30 条（多页翻页去重），「所有结果」的标题一网打尽，再统一按相关度排序。

让 AI 直接调用

// HTTP API

browsesearch 内置一个零依赖的本地 HTTP API。启动后，任何 AI / 脚本都能用 HTTP 调 /search 并读取结构化 JSON 返回值——这正是「让 AI 运行并读取返回值」的入口。

# 1) 启动服务（阻塞，Ctrl+C 退出）
python browsesearch.py --serve --port 8731

# 2) AI / 脚本调用
curl "http://127.0.0.1:8731/search?q=python%20%E5%BC%82%E6%AD%A5%E7%BC%96%E7%A8%8B&limit=30&top=3"

# 或用 POST
curl -X POST http://127.0.0.1:8731/search \
  -H "Content-Type: application/json" \
  -d '{"query":"python 异步编程","limit":30,"top":3}'

返回结构（节选）：

{
  "query": "python 异步编程",
  "engine": "duckduckgo",
  "count": 3,
  "top_match": { "rank":1, "score":8.2, "title":"...", "url":"...", "snippet":"..." },
  "results": [
    { "rank":1, "score":8.2, "title":"...", "url":"...", "snippet":"..." },
    { "rank":2, "score":6.0, "title":"...", "url":"...", "snippet":"..." }
  ]
}

// 5 engines

🔦 DuckDuckGo 默认

🅱️ Bing

结果结构清晰，真实浏览器渲染能稳定拿到标题/链接/摘要；纯 HTTP 也能抓。

🔍 Google

反爬最严，真实 Chromium 渲染的加成最大；DOM 结构偶尔变动，解析为尽力而为。

🐾 百度

服务端渲染，纯 HTTP 即可抓取；结果用容器 mu 属性直接拿真实 URL，免跳转。

🐶 搜狗

服务端渲染；结果链接包一层站内 /link 跳转，已自动顺着 302 解析出真实 URL。
